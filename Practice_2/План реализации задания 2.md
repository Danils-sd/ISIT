# План реализации программного комплекса для сетевого анализа графа ВКонтакте

**Тема:** Программная реализация сбора данных, расчёта метрик центральности и визуализации графа связей учебной группы (Практика №2)  
**Дата составления:** Октябрь 2026 года  
**Дисциплина:** Интеллектуальные системы и технологии  

---

## 1. Цель проекта и границы решения

Целью проекта является разработка модульного, надежного и полностью воспроизводимого программного комплекса на языке Python для:
1. Автоматизированного сбора эго-сети второго порядка участников учебной бригады через API социальной сети «ВКонтакте»;
2. Построения и топологического анализа графа социальных связей;
3. Расчёта ключевых метрик центральности (Betweenness, Closeness, Eigenvector, Degree) для участников группы;
4. Формирования наглядных визуализаций (графа связей с цветовой маркировкой уровней и гистограмм распределения метрик);
5. Экспорта машиночитаемых отчётов (CSV, JSON) и автоматизированной верификации результатов через unit-тесты.

### Границы решения:
* Программный комплекс поддерживает два режима функционирования:
  * **Онлайн-режим (`--fetch`):** Обращение к внешнему VK API, разрешение идентификаторов, пошаговый обход связей и сохранение графа в кэш.
  * **Офлайн-режим (по умолчанию):** Мгновенная загрузка предварительно собранного графа `data/graph.pkl`, расчёт метрик, генерация графиков и отчётов без необходимости наличия токена и сетевого подключения.

## 2. Анализ требований и исходных контрактов данных

### 2.1. Требования из учебных материалов (`ИСиТ пр.pdf`)
* Сбор информации о друзьях и друзьях друзей членов группы из VK;
* Оценка центральности по посредничеству (betweenness), близости (closeness) и собственному вектору (eigenvector) исключительно для членов учебной группы;
* Визуализация графа и сравнительный анализ полученных метрик;
* Обеспечение читаемости кода в соответствии со стандартом PEP8 и принципами Дзена Python.

### 2.2. Контракт исходных данных графа (`graph.pkl`)
* **Тип объекта:** `networkx.Graph` (неориентированный, невзвешенный);
* **Узлы (Nodes):** Целочисленные идентификаторы пользователей `user_id` (тип `int`);
* **Атрибуты узлов:** 
  * `level`: целочисленный уровень вложенности:
    * `0` — член учебной группы (seed nodes);
    * `1` — непосредственный друг члена группы (1-й круг);
    * `2` — друг друга (2-й круг).
* **Свойства графа:** Должен представлять единую связную компоненту (либо выделяется гигантская компонента связности).

### 2.3. Контракт выходного датасета (`centrality.csv`)
Таблица должна содержать следующие обязательные поля:
* `user_id` (`int`): уникальный идентификатор участника группы;
* `degree` (`int`): степень вершины (число инцидентных рёбер в графе);
* `betweenness` (`float`): нормализованная центральность по посредничеству $\in [0, 1]$;
* `closeness` (`float`): центральность по близости $\in [0, 1]$;
* `eigenvector` (`float`): центральность по собственному вектору $\in [0, 1]$;
* `rank_betweenness` (`int`): ранг по посредничеству ($1$ — максимальный показатель);
* `rank_closeness` (`int`): ранг по близости ($1$ — максимальный показатель);
* `rank_eigenvector` (`int`): ранг по собственному вектору ($1$ — максимальный показатель).

## 4. Спецификация программных классов и интерфейсов

### 4.1. Конфигурация (`config.py`)
Определяет глобальные константы, параметры визуализации и пути на основе `pathlib.Path`:
* `GROUP_MEMBERS`: список строковых идентификаторов (`["id593281333", "id503794125", ...]`);
* `MAX_FRIENDS_PER_USER = 30`: порог выборки друзей во избежание комбинаторного взрыва;
* `REQUESTS_PER_SECOND = 5`: частотный лимит VK API;
* `LEVEL_COLORS`: палитра цветов `{0: "#e74c3c", 1: "#3498db", 2: "#2ecc71"}`.

### 4.2. Сетевой клиент `VKClient` (`vk_client.py`)
* **Ответственность:** инкапсуляция обращений к VK API, авторизация по токену, ограничение RPS, устойчивость к ошибкам.
* **Методы:**
  * `__init__(token, requests_per_second)`: инициализация сессии `vk_api`;
  * `_throttle()`: вычисление временной задержки между вызовами;
  * `resolve_id(screen_name: str) -> int`: безопасное извлечение ID (числовой парсинг без сети, либо `utils.resolveScreenName`);
  * `get_friends(user_id: int, limit: int) -> list[int]`: получение списка друзей с обработкой кодов 15 (приватность) и 18 (бан);
  * `get_users_info(user_ids: list[int]) -> list[dict]`: чанкированный сбор профилей (пакетами по 1000).

### 4.3. Строитель графа `GraphBuilder` (`graph_builder.py`)
* **Ответственность:** реализация двухшагового BFS-обхода, разметка уровней вершин, сериализация и десериализация графа.
* **Методы:**
  * `build_two_hop_graph(members: list[str]) -> tuple[nx.Graph, list[int]]`:
    * Шаг 0: добавление семян $S$ с `level=0`;
    * Шаг 1: получение друзей $v \in S$, маркировка `level=1`, добавление инцидентных рёбер;
    * Шаг 2: получение друзей узлов 1-го круга, маркировка `level=2`, добавление рёбер;
  * `save_graph(G, group_ids, filepath)`: запись объекта в бинарный pickle;
  * `load_graph(filepath) -> tuple[nx.Graph, list[int]]`: чтение из pickle с валидацией структуры.

### 4.4. Анализатор центральностей `CentralityAnalyzer` (`centrality.py`)
* **Ответственность:** расчёт графовых метрик, фильтрация компонент, ранжирование, экспорт отчётов.
* **Методы:**
  * `__init__(graph, group_ids)`: проверка связности, выделение гигантской компоненты;
  * `compute_betweenness(normalized=True) -> dict`: расчёт посредничества алгоритмом Брандеса;
  * `compute_closeness() -> dict`: расчёт близости по кратчайшим путям;
  * `compute_eigenvector(max_iter=1000, tol=1e-6) -> dict`: степенной метод с fallback на `numpy.linalg.eigh`;
  * `compute_all() -> pd.DataFrame`: объединение метрик для группы, вычисление целочисленных рангов и сортировка;
  * `get_graph_summary() -> dict`: расчёт глобальных параметров (узлы, рёбра, плотность, связность);
  * `export_reports(df, csv_path, report_json_path, summary_json_path)`: экспорт артефактов.

### 4.5. Визуализатор `GraphVisualizer` (`visualize.py`)
* **Ответственность:** генерация графических представлений в формате PNG высокого разрешения.
* **Методы:**
  * `plot_friends_graph(G, group_ids, betweenness, path)`:
    * Расчёт пружинного расположения узлов алгоритмом Фрюхтермана-Рейнгольда (`nx.spring_layout`, $k=0.15$, $seed=42$);
    * Цветовое кодирование по уровню (`level`);
    * Масштабирование радиуса узла: $R(v) = 60 + 4000 \cdot C_B(v)$;
    * Текстовая аннотация идентификаторов членов учебной группы жирным шрифтом;
  * `plot_centrality_bars(df, path)`:
    * Построение 3-секционного графика `matplotlib.subplots(1, 3)`;
    * Отрисовка горизонтальных столбцов с индивидуальными цветовыми палитрами;
    * Координатная сетка и форматирование меток.

## 5. Пошаговый пайплайн выполнения (Data Flow)

```text
[Конфигурация (config.py)]
           │
           ▼
[VKClient / VK API] ──(Онлайн BFS: 2 шага)──► [GraphBuilder]
                                                     │
                                                     ▼
                                            [data/graph.pkl]
                                                     │
                                                     ▼
                                          [CentralityAnalyzer]
                                                     │
                      ┌──────────────────────────────┴──────────────────────────────┐
                      ▼                                                             ▼
           [data/centrality.csv]                                            [GraphVisualizer]
       [reports/centrality_report.json]                                             │
        [reports/graph_summary.json]                                                ▼
                                                                           [reports/graph.png]
                                                                       [reports/centrality_bars.png]
```

1. **Инициализация:** Чтение аргументов командной строки (`--fetch`, `--no-plot`).
2. **Получение структуры сети:** Либо сетевой сбор эго-сети через VK API, либо быстрое чтение `data/graph.pkl`.
3. **Анализ метрик:** Изоляция гигантской компоненты, расчёт Brandes Betweenness, Closeness и Eigenvector.
4. **Ранжирование:** Сортировка участников, присвоение рангов $1 \dots 5$.
5. **Экспорт данных:** Формирование файлов `centrality.csv` и `centrality_report.json`.
6. **Отрисовка:** Генерация визуализаций `graph.png` и `centrality_bars.png`.

## 6. Стратегия тестирования и контроль качества

Для проверки устойчивости и математической корректности кода разработан модуль `tests/test_core.py`:
1. `test_saved_graph_contract`: проверка наличия файла `graph.pkl`, числа вершин ($1988$), рёбер ($2169$), связности и атрибутов `level`.
2. `test_centrality_csv_contract_and_invariants`: проверка диапазона значений метрик $\in [0, 1]$, корректности схемы колонок и целочисленности рангов.
3. `test_vk_client_offline_resolution`: проверка парсинга ID без обращения к сети и генерации исключений при отсутствии токена для псевдонимов.
4. `test_graph_builder_two_hop_bfs`: тестирование логики BFS на синтетическом моке `MockVKClient` с изоляцией от внешней сети.
5. `test_centrality_calculation_on_canonical_graph`: верификация алгоритмов на графе-звезде ($S_5$), где центр обязан иметь $C_B = 1.0$, а листья — $C_B = 0.0$.
6. `test_visualizer_renders_files`: проверка корректности генерации графических файлов и отсутствия сбоев рендеринга `matplotlib`.

## 7. Управление рисками и граничные случаи

| Риск | Вероятность | Влияние | Мера нейтрализации |
|---|:---:|:---:|---|
| Блокировка запросов VK API по Rate Limit | Высокая | Высокое | Троттлинг запросов (`_throttle`) с задержкой $\ge 0.2$ сек. |
| Наличие приватных/удаленных профилей | Высокая | Среднее | Обработка `ApiError` кодов 15 и 18 с возвратом пустого списка. |
| Несвязность графа при расчёте расстояний | Средняя | Высокое | Автоматическое выделение наибольшей компоненты связности (`subgraph(largest_cc)`). |
| Несходимость степенного метода для Eigenvector | Низкая | Высокое | Автоматический fallback на точный спектральный расчет через `numpy.linalg.eigh`. |
| Отсутствие доступа к интернету при защите | Средняя | Критическое | Реализация полного офлайн-режима на основе кэшированного `data/graph.pkl`. |
