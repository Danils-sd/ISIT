## 1. Описание проекта

Проект реализует бинарную классификацию предпочтений пользователей по типу смартфона (**iPhone** или **Android**) на основе ответов на психологические, поведенческие и демографические вопросы анкеты.

Для классификации используется метод **k ближайших соседей (KNN, k-Nearest Neighbors)**. Модуль классификатора реализован с нуля на `numpy` без применения сторонних ML-библиотек («черных ящиков») в ядре модели. Для удобства работы с анкетой разработано настольное приложение с графическим интерфейсом на Tkinter.

### Обозначение классов:
* `0` — **iPhone**
* `1` — **Android**

## 3. Датасет и предобработка данных

Обучающий датасет (`data/dataset_normalized.csv`) содержит **44 строки** и **20 числовых признаков** (а также целевую колонку `phone`):

1. **Бинарные вопросы (14 вопросов)**:
   * Вопросы с двумя альтернативами («Да»/«Нет», «Комфортно»/«Дискомфортно», «Рационально»/«Эмоционально» и т. д.) кодируются значениями `0.0` и `1.0`.
2. **Категориальный вопрос — цвет глаз (1 вопрос)**:
   * Кодируется методом **One-Hot Encoding** шестью признаками: `eye_blue`, `eye_brown`, `eye_gray`, `eye_gray_blue`, `eye_green`, `eye_other`. В каждой строке строго один из них равен `1.0`, остальные — `0.0`.
3. **Числовые вопросы (2 вопроса)**:
   * Приводятся к диапазону $[0, 1]$ с помощью Min-Max масштабирования:
     * `phone_change_years` (частота смены телефона в годах):
       $$\text{years}_{\text{norm}} = \text{clip}\left(\frac{\text{years} - 2}{8 - 2}, 0, 1\right)$$
     * `games_hours` (часы видеоигр в неделю):
       $$\text{games}_{\text{norm}} = \text{clip}\left(\frac{\text{hours}}{40}, 0, 1\right)$$

> **Примечание:** 
> * Вопрос о ближайшей станции метро исключён из интерфейса, так как признак для него отсутствует в нормализованном обучающем датасете.
> * Целевой вопрос («У тебя айфон или андроид?») исключён из видимых вопросов анкеты и служит только целевой меткой при обучении.

## 4. Как работает классификация (KNN)

1. **Векторизация ответов**: введённые пользователем в интерфейсе ответы валидируются и преобразуются в 20-мерный вектор $\vec{x} \in [0, 1]^{20}$ в строгом порядке `FEATURE_COLUMNS`.
2. **Расчёт расстояний**: вычисляется евклидово расстояние от вектора пользователя $\vec{x}$ до каждого вектора $\vec{x}_i$ обучающей выборки:
   $$d(\vec{x}, \vec{x}_i) = \sqrt{\sum_{j=1}^{20} (x_j - x_{i,j})^2}$$
3. **Отбор соседей**: отбираются $K$ обучающих объектов с наименьшим расстоянием до $\vec{x}$.
4. **Голосование большинства**: среди выбранных $K$ соседей подсчитывается количество голосов за класс `0` (iPhone) и класс `1` (Android).
5. **Разрешение ничьих**: при равенстве голосов детерминированно выбирается класс соседа, находящегося ближе всего к классифицируемому объекту.

## 5. Подбор $K$ и оценка качества

Подбор гиперпараметра $K$ проводился в модуле `quality_check.py` методом **5-кратной стратифицированной кросс-валидации (Stratified K-Fold)** по 5 случайным сидам (суммарно 25 оценок для каждого значения $K$).

Критерий выбора — максимизация **Macro F1-score**, так как датасет имеет дисбаланс классов (16 iPhone vs 28 Android):

| K | Mean Accuracy | Std Accuracy | Mean Macro F1 | Std Macro F1 | Примечание |
|---|---|---|---|---|---|
| 1 | 0.422 | ±0.134 | 0.378 | ±0.138 | Чувствительность к шуму |
| 3 | 0.481 | ±0.123 | 0.418 | ±0.121 | |
| 5 | 0.583 | ±0.144 | 0.521 | ±0.155 | |
| **7** | **0.662** | **±0.127** | **0.602** | **±0.145** | **Оптимальное значение (зафиксировано в config.py)** |
| 9 | 0.651 | ±0.125 | 0.583 | ±0.149 | |
| 11 | 0.624 | ±0.121 | 0.525 | ±0.156 | |
| 13 | 0.624 | ±0.129 | 0.530 | ±0.166 | |
| 15 | 0.584 | ±0.129 | 0.473 | ±0.141 | |
| 17 | 0.626 | ±0.118 | 0.511 | ±0.153 | |
| 19 | 0.646 | ±0.154 | 0.509 | ±0.192 | |

* **Baseline (мажоритарный класс Android)**: Accuracy = 0.637, Macro F1 = 0.389.
* Модель с **$K = 7$** превосходит базовый классификатор по Macro F1 (**0.602** против 0.389) и обеспечивает наилучший баланс между смещением и дисперсией.
* На контрольной отложенной выборке (holdout, 11 объектов) модель достигает **Accuracy = 90.9%** и **Macro F1 = 89.5%**.

## 6. Установка и запуск

### Требования
* Python 3.10+
* Tkinter (входит в стандартную поставку Python)

### Установка зависимостей
```bash
pip install -r requirements.txt
```

### Запуск пользовательского приложения
```bash
python app.py
```

### Запуск проверки качества и генерации отчётов
```bash
python quality_check.py
```
Отчёты и графики сохраняются в папку `reports/`.

### Запуск автоматических тестов
```bash
python -m unittest discover -s tests -v
```
Тесты проверяют целостность контракта обучающего датасета, корректность нормализации, логику KNN, обработку ничьих и отсутствие артефактов интерфейса при переходе между вопросами.
