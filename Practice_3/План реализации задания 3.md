# План реализации программного комплекса для сравнения vision-LLM (Практика №3)

**Тема:** Бинарная классификация самолётов («военный» / «гражданский») двумя vision-LLM через Groq и Cloudflare Workers AI, сравнение метрик  
**Дата составления:** Октябрь 2026 года  
**Дисциплина:** Интеллектуальные системы и технологии  

---

## 1. Цель проекта и границы решения

Цель — построить **воспроизводимый пайплайн** для:
1. Загрузки сбалансированного датасета изображений самолётов с нетривиальными случаями;
2. Отправки каждого изображения в **две** vision-LLM (`Qwen3.8-27B` через Groq, `Llama-3.2-11b-vision` через Cloudflare);
3. Нормализации свободного текстового ответа в метку `{civil, military, unknown}`;
4. Расчёта accuracy / precision / recall / F1 / confusion matrix по положительному классу `military`;
5. Сохранения предсказаний и метрик в CSV и вывода сравнительной таблицы.

### Границы решения
* **Не решаем:** обучение/дообучение моделей — используем только inference через облачные API.
* **Не решаем:** мультиклассовую классификацию (только бинарная).
* **Не решаем:** локальный запуск моделей — только облачные провайдеры.
* **Ограничение задания:** ≤ 30 изображений на модель (лимиты бесплатных запросов).

---

## 2. Анализ требований и контрактов данных

### 2.1. Требования из `ИСиТ пр (1).pdf` (Задача №3, слайд 14)
* Решить задачу «военный / гражданский самолёт по фотографии»;
* Использовать провайдеров LLM на Hugging Face (в реализации — Groq + Cloudflare Workers AI как практическая замена с теми же лимитами);
* Сравнить метрики двух LLM;
* Выборка должна содержать нетривиальные случаи;
* Размер выборки — ~30 изображений.

### 2.2. Контракт входного датасета
├── civil/ c01.jpg ... c13.jpg
└── military/ m01.jpg ... m13.jpg
* Допустимые расширения: `.jpg`, `.jpeg`, `.png`, `.webp` (множество `VALID_EXT`);
* Имена файлов — произвольные, но стабильные (для трассировки ошибок);
* Баланс классов: 13 / 13.

### 2.3. Контракт `results/predictions.csv`
| Колонка | Тип | Описание |
|:---|:---|:---|
| `model` | str | Название модели из `MODELS` |
| `image` | str | Имя файла изображения |
| `true_label` | str | `civil` / `military` |
| `raw_response` | str | Сырой ответ модели (обрезан до 120 символов) |
| `predicted_label` | str | `civil` / `military` / `unknown` |

### 2.4. Контракт `results/metrics.csv`
| Колонка | Тип | Описание |
|:---|:---|:---|
| `model` | str | Название модели |
| `n_total` | int | Число изображений |
| `n_unknown` | int | Число ответов `unknown` |
| `accuracy` | float | Доля верных |
| `precision_military` | float | Precision по `military` |
| `recall_military` | float | Recall по `military` |
| `f1_military` | float | F1 по `military` |
| `TP / TN / FP / FN` | int | Матрица ошибок |
