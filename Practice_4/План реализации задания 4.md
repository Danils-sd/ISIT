## 1. Какое решение делаем

Небольшая консольная программа на Python: один файл с функциями среды, Q-learning, проверки и построения графика. Единственная внешняя зависимость — Matplotlib. Используем стандартные `random`, `itertools`, `collections` и `pathlib`.

Пять стаканов вместимостью по 4 порции, общий объём 10, цель `[2, 2, 2, 2, 2]`. За шаг переливаем одну порцию. Продолжение переливаний из того же источника не увеличивает число поднятий.

Не добавляем веб-интерфейс, нейросеть, Gymnasium, базу данных, сложную систему настроек или разбиение на множество модулей. Для этой работы достаточно функций и констант в начале файла.

## 3. Реализовать среду

В начале `main.py` задать константы:

```text
N_GLASSES = 5
CAPACITY = 4
TOTAL = 10
TARGET = 2
MAX_STEPS = 200
SEED = 42
```

Нужны функции:

- `is_goal(volumes)` — все пять объёмов равны цели.
- `valid_actions(volumes)` — пары разных стаканов с непустым источником и незаполненным приёмником.
- `step(state, action)` — новое состояние, награда, признак успеха и число новых поднятий: 0 или 1.
- `optimal_lifts(volumes)` — число исходных объёмов выше цели; используется при проверке.

Состояние — `(v1, v2, v3, v4, v5, held)`, где `held = -1` при старте. Смена источника автоматически означает поставить предыдущий стакан и поднять новый. Штраф за лимит шагов начисляется в цикле эпизода, где известен номер шага.

До обучения проверить вручную заданными действиями:

1. Переливание сохраняет сумму 10 и диапазон объёмов от 0 до 4.
2. Два переливания подряд из одного источника в разные приёмники дают одно поднятие.
3. Возврат к прежнему источнику после смены стакана считается новым поднятием.
4. Для `[4, 3, 2, 1, 0]` последовательность из исследования даёт цель за два поднятия.
5. Для `[2, 2, 2, 2, 2]` нужны ноль действий и ноль поднятий.

Эти проверки можно выполнить короткими `assert` перед обучением; отдельный тестовый фреймворк не требуется.

## 4. Реализовать Q-learning

Получить все начальные распределения через `itertools.product(range(CAPACITY + 1), repeat=5)`, оставив только варианты с суммой `TOTAL`. Проверить, что их 381; цель исключить из выборки для обучения. В начале эпизода выбирать случайное распределение из оставшихся 380 и устанавливать `held = -1`.

Q-таблица — обычный словарь с ключом `(state, action)`. Неизвестная оценка равна нулю. Доступ к отсутствующей записи не должен менять таблицу во время итоговой проверки.

Начальные параметры эксперимента:

| Параметр | Значение |
| --- | --- |
| Эпизоды | 100 000 |
| `alpha` | 0.2 |
| `gamma` | 1.0 |
| `epsilon` | Линейное снижение от 1.0 до 0.05 за первые 80% эпизодов, затем 0.05 |
| Предел шагов | 200 |
| Награда за успех | +10 |
| Штраф за поднятие | -1 |
| Штраф за переливание | -0.001 |
| Штраф за неудачу по лимиту | -10 |

Цикл эпизода:

1. Получить допустимые действия.
2. Выбрать случайное действие с вероятностью `epsilon`, иначе действие с максимальной Q-оценкой. При равенстве оценок во время обучения выбирать случайно.
3. Выполнить переливание и получить награду.
4. Если это последний шаг и цель не достигнута, добавить штраф за неудачу.
5. Обновить Q-оценку. Для завершённого эпизода использовать только текущую награду, без следующего максимума.
6. Накопить суммарную награду и число поднятий.
7. Завершить эпизод при успехе либо исчерпании лимита.

Сохранять в списке суммарную награду каждого эпизода. Печатать короткий прогресс, например каждые 10 000 эпизодов. На этом этапе не заявлять о достижении оптимума до итоговой проверки.

## 5. Проверить обученного агента

После обучения заморозить таблицу и установить `epsilon = 0`. При одинаковых максимальных Q-оценках использовать фиксированный порядок действий, чтобы проверка была воспроизводимой.

Запустить агента на всех 380 неравных начальных распределениях с пустыми руками. Здесь проверяется покрытие выбранной конечной среды; поскольку эти состояния могли встречаться в обучении, результат не является проверкой обобщения на неизвестные вместимости или объёмы.

Для каждого случая записать:

- достигнута ли цель за 200 шагов;
- сколько было поднятий и переливаний;
- теоретический минимум поднятий;
- совпало ли число поднятий с минимумом.

В консоль и `results.txt` вывести число проверенных случаев, долю успешных и долю оптимальных решений от всех 380 случаев. Неудачи не исключать из знаменателя. Отдельно проверить уже равное состояние: оно решено сразу, с нулём поднятий.

В том же файле показать несколько трасс, обязательно включая `[4, 3, 2, 1, 0]`. Для каждого шага указать источник, приёмник, новые объёмы и накопленное число поднятий. Если есть ошибки, сохранить исходные распределения и результат проверки для разбора.

Целевой критерий готовности — все 380 случаев решены с минимальным числом поднятий. Если первая настройка обучения его не достигает, сначала увеличить число эпизодов и повторить проверку. При необходимости скорректировать темп снижения `epsilon` или `alpha`, сохраняя тот же простой алгоритм. Не исправлять действия агента эталонным алгоритмом и не выдавать желаемые проценты за измеренные.
